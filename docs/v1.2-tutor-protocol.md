# Gallop v1.2 Tutor Protocol

Status: implemented protocol boundary; Runtime Bridge stage implemented locally

Version: `1.2`

Gallop v1.2 has one bidirectional protocol for four permanent tutor surfaces:

| Subject | Stable tutor ID |
| --- | --- |
| Mathematics | `mathematics-tutor` |
| Statistics & Econometrics | `statistics-econometrics-tutor` |
| Finance | `finance-tutor` |
| CS & AI | `cs-ai-tutor` |

They are policies over one Gallop system, not four backends. Gallop remains
headless. This protocol does not require DeepTutor and does not create a learner
dashboard or a manual CLI workflow.

## Tutor to Gallop

The normative schema is
[`tutor-event-v1.2.schema.json`](../gallop/schemas/tutor-event-v1.2.schema.json).
Every event carries a stable event, session and tutor identity; one of the four
subjects; an explicit timezone-bearing occurrence time; a bounded structured
payload; and learning-scoped provenance.

Supported event types are:

`session_start`, `context_request`, `concept_exposed`, `task_issued`,
`learner_attempt`, `hint_given`, `feedback_given`, `candidate_assessment`,
`mistake_observed`, `prerequisite_issue`, `repair_attempt`,
`reconstruction_attempt`, `independent_success`, `oral_response`,
`proof_submission`, `coding_submission`, `simulation_result`, `paper_activity`,
`checkpoint`, `session_idle`, and `session_finalize`.

The schema requires task, attempt, concept, response and evidence references
where the event type needs them. Payloads reject unknown top-level fields so a
whole chat transcript, credentials or unrelated personal material cannot be
silently attached as an extension. Large artifacts remain external and are
referenced rather than embedded.

`session_finalize` is a lifecycle observation, not a durability boundary.
Every meaningful checkpoint has its own stable event ID and is intended to be
committed independently by the runtime bridge.

## Gallop to Tutor

The normative schema is
[`tutor-directive-v1.2.schema.json`](../gallop/schemas/tutor-directive-v1.2.schema.json).
Directives carry stable directive/session IDs, the subject, issuance time,
source journal event IDs, and an explicit `ADVISORY` authority marker.

Supported directive types are:

`learning_context`, `training_zone`, `scaffold_level`, `target_capability`,
`prerequisite_focus`, `task_type`, `review_due`, `retest_due`,
`independence_requirement`, `assessment_boundary`, `next_action`, and
`unfinished_work`.

The protocol distinguishes current and target capability. A target is never a
claim about current capability. Directives communicate Gallop policy; the tutor
still chooses explanations, wording and pedagogical interaction.

## Authority and evidence safety

Tutor assessments are always `CANDIDATE_EVIDENCE`. The protocol has no
`MASTERED` authority value. Tutor-originated data cannot assert a human
attestation, and a directive can never be authoritative.

Actual assistance controls independence classification. Any nonzero assistance
or AI assistance contradicts `INDEPENDENT`; AI-generated code cannot be
independent coding evidence. These checks happen at protocol validation before
a future bridge may append anything to the journal.

The journal remains authoritative. Tutor events are observations or candidate
evidence until existing Gallop evidence rules admit them. Obsidian remains a
projection and cannot send authoritative progression mutations through this
contract.

## Stable identity and retries

IDs are caller-supplied bounded tokens. A future runtime bridge must use the
event ID as its idempotency key: an exact retry is a no-op and the same ID with
different normalized content is a conflict. The protocol deliberately does not
derive identity from chat text or depend on chat history.

The source schemas and validator are side-effect free. They do not open a
journal, create directories, read a Vault, contact a provider or write a
projection. The transport-neutral Runtime Bridge now admits validated lifecycle
events to the append-only journal. Candidate assessments and independent-success
claims are atomically mapped into existing Elite Evidence as unconfirmed Tutor
provenance. Each durable event now refreshes privacy-filtered session, concept,
and mistake notes in the existing Obsidian subject structure. Context Builder
is the next sequential v1.2 phase.
