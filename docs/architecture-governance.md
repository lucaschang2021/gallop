# Architecture Governance

`ARCHITECTURE.toml` is the executable contract for Gallop's current architecture.
The contract protects the useful chain already present in the project:

> Evidence → append-only Journal → deterministic Replay → Domain Decisions →
> Application Orchestration → External Adapters / Projections

This is a drift-control boundary, not a template-driven rewrite. Stable v1
journal, mastery, queue, DeepTutor, Obsidian, and Reader behavior remain intact.

## Authority and evidence

The Event Journal is authoritative. `derived-state.json`, prepared artifacts,
Obsidian Markdown, and Gallop-Reader are cache, projection, or export data. They
may be rebuilt or safely regenerated; none may create an authoritative learning
transition by being edited.

| Evidence authority | Meaning | May directly promote mastery? |
|---|---|---|
| `OBSERVATION` | Tutor-reported exposure, weakness, or question | No |
| `ATTEMPT` | Work was attempted; completion and quality still need authority | No |
| `ASSESSMENT` | Explicit human-confirmed evaluation matching the assigned work | Only through the mastery gate |
| `VERIFIED_INDEPENDENT_EVIDENCE` | Passing, confirmed, zero-hint compatible evidence with provenance | Only through the applicable evidence gate |
| `PROVIDER_OUTPUT` | Practice material generated by DeepTutor or another provider | No |
| `SYSTEM_DERIVED_STATE` | Deterministic replay result, queue item, readiness, or recommendation | No; it is derived |

Prepared work is not completed work. AI-generated solutions are never
independent evidence. Provider failure can change a job or queue status but
cannot lower or promote mastery.

## Layer responsibilities

| Layer | Owns | Must not own |
|---|---|---|
| Domain | Pure mastery and progression decisions from explicit inputs | Files, environment, clock acquisition, network, CLI, adapters |
| Application | Locks, workflow coordination, calls to domain, event append, projection dispatch | New capability, zone, scaffolding, prerequisite, struggle, gain, or mentor-role formulas |
| Persistence / Journal | Transactions, append-only semantics, hashes, conflict detection | Learning policy decisions |
| Adapters | DeepTutor, Obsidian, and mock translations at external boundaries | Reducer mutation or assessment authority |
| Projection / Views | Human-readable rendering and filtered export | Authoritative state mutation |
| CLI | Parse explicit user intent and invoke application operations | Domain decisions |
| Bootstrap / Config | Bind validated runtime paths and load versioned policy data | Hidden import-time lifecycle actions |
| Schemas | Versioned input, event, and policy contracts | Runtime state |

## Progressive Mentorship boundary

`gallop.progression` is the deterministic domain. It has no EventStore,
filesystem, DeepTutor, Obsidian, CLI, subprocess, network, environment, or
implicit current-time dependency. `ProgressionContext` supplies the state,
target, subject policy, and readiness dimensions explicitly. Separate modules
own capability, scaffolding, prerequisites, struggle, gains, zones, and mentor
role. `gallop.mentorship` remains the compatibility and policy-loading facade.

The target ceiling stays fixed. Current capability is evidence-derived;
training difficulty adapts, assistance fades one step at a time, and
independence remains the destination. A recommendation has
`queue_mutation: NONE`; the v1 queue is still the only scheduler.

## `state.py` responsibility map

| Responsibility | Current owner | Governance |
|---|---|---|
| A. Event reducer and replay | `automation/state.py:replay` | Frozen deterministic v1 behavior; historical replay must remain exact |
| B. Mastery policy | `automation/state.py:mastery_gate` | Human assessment authority only; failure may reduce confidence without erasing established mastery |
| C. Review scheduling | `automation/state.py:training_candidate` with explicit `day` | No implicit clock in the decision function |
| D. Training selection | `automation/state.py:training_candidate` plus versioned subject policy | Existing v1 behavior; no RC2 progression formulas added |
| E. Progression policy | `gallop.progression` | Independent pure domain modules; never added to `state.py` |

## Time and side effects

Domain decisions receive dates and timestamps as input. The application may
acquire the current time for a new command or event, then records that time so
replay does not ask the clock again. Importing `gallop` must not create state,
write a Vault, launch DeepTutor, append an event, or start a process.

Policy data is separate from runtime state and evidence. The architecture
contract assigns a version and shape to each policy catalog. The gate validates
all four supported subjects and the mentorship catalog's embedded schema
version; subject-specific data changes parameters and labels, never engine code.

## Architecture Gate

Run:

```bash
python scripts/check_architecture.py
```

The report has `existing`, `introduced`, and `resolved` findings. CI fails only
when `introduced` is non-empty or the contract itself is invalid. The current
baseline contains no accepted violations. Size thresholds emit warnings and
governed-file growth fails until a responsibility review deliberately updates
the recorded line baseline; file size alone never triggers automatic splitting.

The gate checks forbidden dependency directions, hidden domain time, domain
module state/import side effects, adapter access to reducer internals,
projection access to authoritative mutation, policy validity, new domain
methods in `Automation`, progression methods in `state.py`, and growth of the
four named hotspots.
