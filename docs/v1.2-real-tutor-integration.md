# Gallop v1.2 Real Tutor Integration

Status: **transport implemented; real learner dogfood pending**

Gallop exposes one headless STDIO MCP server per Tutor subject. The four server
processes share one learner Journal but each launch is bound to exactly one of:

| Server | Subject | Tutor ID |
| --- | --- | --- |
| `gallop-mathematics-tutor` | `mathematics` | `mathematics-tutor` |
| `gallop-statistics-tutor` | `statistics` | `statistics-econometrics-tutor` |
| `gallop-finance-tutor` | `finance` | `finance-tutor` |
| `gallop-cs-ai-tutor` | `cs-ai` | `cs-ai-tutor` |

The subject is a process-level binding, not a caller-controlled field. A tool
call whose event subject, Tutor ID, or recorder differs from that binding fails
before the Journal is opened. The transport contains no model call, no
DeepTutor dependency, and no UI.

## Tools

- `open_or_resume_session` commits the session start and returns bounded
  journal-derived context.
- `get_learning_context` and `get_session` are read-only.
- `record_learning_event`, `checkpoint_session`, and `finalize_session` append
  validated events before refreshing owned Obsidian projections.

Tool metadata accurately marks reads and writes. The server instructions require
stable event IDs, incremental checkpoints, candidate-only Tutor assessments,
explicit human confirmation, and the No-Agent Coding boundary.

## Real learner safety

The learner configuration must name an existing Obsidian Vault, a separate
private Journal root outside cloud storage, the existing `Gallop-Reader`, a
separate export-state directory, and the validated iCloud binding. The Journal
is authoritative. Projection failure is reported while the committed event
remains recoverable. Synthetic events are rejected in the learner namespace.

Before the first real write, verify all paths and the iCloud object, parent,
provider database, placeholder identity, pin state, and sync state. Preserve a
backup of every existing file that can receive a Gallop managed region. If any
identity or ownership check fails, do not write or attempt provider repair.

## Acceptance boundary

Protocol and isolated MCP restart tests are implementation evidence, not real
dogfood. Release readiness still requires actual learner interactions in all
four Tutors, fresh-chat continuation, abrupt-close recovery, duplicate replay,
projection recovery, mobile visibility where the validated path permits, and
the unchanged RC2 evidence, mastery, independence, queue, and privacy gates.
