# Gallop v1.0.0

Gallop Automation V1 completes the full learning-operations loop:

Tutor → Intake → Event Store → Learning State → Training Queue → DeepTutor
→ Practice / Assessment → State Transition → Obsidian → Gallop-Reader

## Highlights

- Tutor intake for mathematics, statistics/econometrics, finance, and CS/AI
- Append-only event logging and replayable learner state
- Mastery Safety Gate and deterministic Training Queue
- DeepTutor bridge with submit/poll/collect
- Late-result recovery, idempotent collection, and safe retries
- Process tracking and crash recovery
- Obsidian projections and Gallop-Reader publishing
- Explain / audit provenance
- Golden E2E and real DeepTutor E2E validation

## Philosophy

Gallop automates learning operations, not learning itself.

AI should organize deliberate practice, not outsource thinking.

## Boundaries

- Real learner actions are required for proof, coding, oral examination,
  simulation, and assessment. Generated choice questions are supplementary.
- Integration/synthetic data must never modify real mastery.
- Obsidian remains the user-owned learning store. For new Automation V1
  records, the append-only event journal is authoritative for replay; Markdown
  state is a derived view. Legacy learning state is not silently migrated.
- DeepTutor remains the external practice execution layer.
- Provider exactly-once execution is not claimed for an uncertain process
  launch. Retries are refused while an existing attempt is live or uncertain.
- Private responses, credentials, runtime logs, local paths and cloud state
  are excluded from the source release.

## Compatibility

Existing legacy commands remain available. Automation `prepare --send` now
returns a durable job ID; use `poll JOB_ID` and `collect JOB_ID` before starting
the prepared practice. A job's completion means material is ready, not that
the learner has completed or mastered the exercise.
