# Gallop v1.2 Real Four-Tutor Dogfood Acceptance

Date: 2026-09-14

Status: **PASS — learner outcomes retained without promotion**

This record covers controlled real use of the four subject-bound GPT Tutor MCP
servers against the existing learner Journal, Obsidian Vault, and validated
one-way Gallop-Reader binding. It records runtime behavior, not a claim that
every learner answer was correct or that Gallop's mastery model is an educational
measurement instrument. Private answers, local paths, configuration, and raw
Journal data are deliberately excluded.

## Recovery and idempotency

- Meaningful work was committed incrementally before tutoring continued.
- An intentional desktop termination left the Mathematics session active. After
  restart, `open_or_resume_session` returned `created=false` and reconstructed
  the existing session, mistake, assisted evidence, human attestation, and prior
  checkpoints from the Journal.
- A byte-equivalent retry of the human-confirmation event returned
  `duplicate=true`, reused both Journal identities, and wrote zero projection
  files.
- The later fresh chat received only the stable Mathematics session ID. Its
  independent proof assessment and checkpoint appeared in the original Journal
  without access to the earlier transcript.

## Projection and mobile continuity

Every Tutor write committed to the Journal before refreshing owned Obsidian
views. Real events produced subject Session, Concept, Mistake, Home, and Gallop
Automation projections. A Reader publication dry-run validated the existing
iCloud object and ownership boundary before mutation:

- readable notes: 27;
- generated root notes: 2;
- excluded directories: 1;
- synthetic notes filtered: 1;
- quarantined notes: 0.

The controlled publication wrote 27 owned files and retained 2 unchanged files.
The post-publication dry-run requested zero writes. This proves safe Reader
publication recovery from its older snapshot. A separate real projection
recovery check copied and hash-verified one newly generated, fully Gallop-managed
Finance session note before removing it. Projection correctly failed closed
with `Managed region was removed; refusing to overwrite`; the Journal and
derived state hashes remained unchanged. The verified backup was restored, its
SHA-256 matched the original, and a full 27-view projection check then returned
`written=0`. Gallop therefore preserved ownership safety rather than silently
recreating a path whose removal could have been a user decision. The learner then explicitly
confirmed that at least one of the requested Finance or CS/AI session notes was
visible in the existing Gallop-Reader on mobile Obsidian. No phone-to-Vault
write, provider repair, replacement Reader, migration, or unknown-content
deletion occurred.

incremental checkpointing, abrupt termination recovery, exact duplicate
