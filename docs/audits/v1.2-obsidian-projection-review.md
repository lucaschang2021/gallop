## Projection behavior

Each committed Tutor event triggers a best-effort projection after the journal
transaction. The derived notes include:

- stable session metadata, status, topics, task/attempt IDs, assistance,
  mistakes, candidate-evidence references, unfinished work, and next actions;
- one concise session record under the subject's `Sessions` directory;
- derived concept summaries under `Concepts`;
- first-class failure-taxonomy notes under `Mistakes`.

Raw prompts and learner response references are deliberately not rendered.
Potential credentials, machine paths, and private references are replaced with
a fixed omission marker. Synthetic integration notes remain visibly marked and
are excluded by existing Reader export filters.

All writes reuse the existing managed-region ownership check, whole-plan
preflight, atomic file replacement, and projection receipt. User text outside a
managed region is preserved. Obsidian remains derived human-readable memory and
cannot mutate journal authority.

## Failure and growth review

Projection failure returns `FAILED` with only the exception type and
`journal_durable: true`; the committed event is preserved and a later operation
or explicit project call can retry. No error detail or learning content is
leaked through diagnostics.

The Runtime Bridge grows from 158 to 169 lines solely for best-effort projection
status. `gallop/projections/tutor.py` begins with a reviewed 128-line boundary.
Architecture violations remain zero after updating these explicit baselines.
