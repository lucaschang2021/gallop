# v1.2 Context Builder Review

Status: PASS

Review date: 2026-09-13

Base: `20c434b` (Obsidian Projection stage)

## Authority and determinism

The Context Builder reads one replay-derived state snapshot and emits a
versioned `learning_context` directive with `ADVISORY` authority. Subject,
session and source-event identities must match between the envelope and packet.
The directive ID derives from the subject, session and journal head, while its
issuance time comes from the latest durable session event. Repeating the read at
the same head therefore returns exactly the same document.

Current capability is evidence-derived and is distinct from the latest explicit
target. Tutor candidate evidence remains `confirmed: false`; observing it can
make the context `EXPOSED`, but cannot establish independent capability or
mastery. Building context does not mutate the V1 queue or any learning state.

## Bounds, isolation and privacy

Packets enforce caller bounds of 1-50 items and 2,000-20,000 canonical JSON
characters. Deterministic truncation records whether and how many items were
omitted. Only the requested subject's Tutor sessions, Tutor events, evidence,
target and queue rows are selected.

The builder accepts state, not filesystem paths. It does not read the Obsidian
Vault, Reader, chat history or external providers. Raw prompt and learner
response references are not fields in the packet. Bounded free text is filtered
for credential forms, embedded credentials, NUL bytes and local machine paths;
matches become a fixed omission marker.

Integration coverage includes cross-subject exclusion, an unrelated Vault
sentinel, private prompt/response references, candidate-evidence authority,
current-versus-target separation, exact repeatability, queue invariance and
forced item/character truncation.

## Responsibility growth

`gallop/tutor/context.py` is a reviewed application-layer boundary dedicated to
deterministic journal-derived context. The Runtime Bridge only snapshots state,
calls the builder and wraps the packet in the protocol directive. Their exact
line baselines are recorded in `ARCHITECTURE.toml`; no architecture violation is
accepted or suppressed.
