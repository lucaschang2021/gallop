# v1.2 Fresh-Chat Restore Review

Status: PASS

Review date: 2026-09-13

Base: `b324e2a` (Context Builder stage)

## Automatic continuity

`open_or_resume_session` now returns a learning-context directive without a
separate learner action. A new session first commits its stable start event,
then builds context from replay-derived Journal state. Resuming the same session
at the same Journal head returns the same directive.

The restore packet intentionally ignores generic `session_start` summaries when
selecting the previous relevant summary. A fresh Session N+1 therefore receives
the latest meaningful subject summary, concept, candidate evidence, mistakes,
unfinished work and next action from Session N rather than a bridge boilerplate
message.

## Interruption and failure behavior

The integration scenario leaves Session N active, closes the owning runtime,
opens a new runtime over the same append-only Journal, and creates Session N+1
with a later explicit clock. The complete committed learning state is restored
without passing any prior chat content to the new process.

If bounded context construction or validation fails, the new session start
remains durable and the result reports `context_restore: FAILED`, exception type
and `journal_durable: true`. It returns `context: null`; the Tutor can continue
teaching but has no basis to claim restored learning state. Error details and
learning content are not exposed in diagnostics.

## Authority and scope

Restore is read-only over replayed state after the session-start append. It does
not confirm Tutor candidate evidence, change mastery, refresh the V1 queue, read
the Vault, invoke DeepTutor or depend on model chat history. The Runtime Bridge
growth is limited to the automatic restore wrapper and status diagnostics; the
reviewed line baselines are recorded in `ARCHITECTURE.toml` with no accepted
architecture violation.
