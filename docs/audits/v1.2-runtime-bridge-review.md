# v1.2 Runtime Bridge Responsibility Review

Status: PASS

Base: `70d7bbf9f4e6fe2ba8807a84e12b21eb20fc8b3b` (Tutor Protocol stage)

## Scope

The Runtime Bridge stage adds a transport-neutral application boundary for
custom ChatGPT tool or MCP transport adapters. It exposes JSON operations for
opening/resuming a tutor session, recording a learning event, checkpointing,
finalizing, and reading derived session state. It does not expose a learner UI,
write an Obsidian projection, convert candidate evidence into mastery, or depend
on DeepTutor.

## Governed-file growth review

`gallop/automation/service.py` changes from 561 to 568 lines. The mutation
coordinator becomes a public application method for the bridge, while legacy
DeepTutor and Jobs imports become lazy. A compatibility factory retains the
existing test/extension patch seam without importing DeepTutor at bridge import
time. The seven-line increase is dependency isolation, not a new domain decision
or projection responsibility.

`gallop/automation/state.py` changes from 193 to 196 lines. The only added
responsibility is dispatching `tutor_event` to the dedicated derived-state
reducer. Historical journals without tutor events produce the exact frozen V1
state and projection.

`gallop/tutor/bridge.py` begins with a 139-line reviewed baseline. Its role is
application orchestration over the existing journal and clock ports. Its soft
and hard review thresholds are recorded in `ARCHITECTURE.toml`.

The cross-process file lock moves unchanged from the legacy DeepTutor jobs
module into `gallop/automation/locking.py`. This lets the core Automation import
without importing DeepTutor. The legacy jobs module keeps the same public
`file_lock` name through an ordinary import, preserving compatibility.

## Authority and failure behavior

- Exact retries use the caller's stable Tutor event ID and are idempotent.
- Reusing that ID with different content fails as `JournalConflict`.
- A session must be opened before other events.
- Tutor/subject changes, a second start, backward chronology, and events after
  finalization fail closed.
- A checkpoint is committed before any finalization and survives reopening.
- Tutor lifecycle events add no mastery evidence and make no V1 queue change.
- Importing the Runtime Bridge imports no DeepTutor module and performs no
  filesystem mutation.

The revised architecture line baselines are admitted only for these reviewed
changes. Architecture `existing`, `introduced`, and `resolved` must remain
empty after the update.
